# Milestone 0.13 Plan: the bootloader, GRUB → Limine

**Base:** `main` at `0c0683b` (the `v0.12` code, the README commit `2b3522f`, the D6 workflow commit). 0.13 work goes on `wip/0.13`; `main` receives only the single milestone commit.

## 1. Goal and scope

- **Only the bootloader changes.** The ISO boots through Limine v12.9.3 instead of GRUB, BIOS only, still Multiboot 1 with the a.out kludge.
- **No kernel change is expected** apart from the version string. At the milestone, the byte diff of `madire.kernel` against v0.12's is reported: it must differ only in the version string.
- **Not in scope:** UEFI, Limine's own boot protocol (framebuffer, all CPU cores, ACPI), new commands. MOCS stays v0.7 (no command changes).

## 3. Checks

**Counts.** Today 1222 (0.3: 150 · 0.4: 30 · 0.5: 32 · 0.6: 49 · 0.7: 96 · 0.8: 32 · 0.9: 139 · 0.9.1: 32 · 0.9.2: 25 · 0.10: 253 · 0.11: 233 · 0.12: 151) and 55 unit suites. The exact list and number are agreed before stage 3a. Unit suites stay **55**.

**Proposed `[0.13]` checks:**
1. `scripts/check-multiboot.py` **passes on the real kernel** (`build/madire.kernel`).
2. It refuses a wrong magic.
3. It refuses a wrong checksum.
4. It refuses a.out fields outside the file.
5. Limine's files in the ISO that stay byte-identical to the pinned package (per stage 1's `bios-install` finding) match their SHA-256.
6. The ISO holds Limine's `COPYING` and `3RDPARTY.md`, and no GRUB file.
7. Every program module in `limine.conf` has `module_string` set to its file name.
8. A module without `module_string` is refused, with its log line.
9. That boot still reaches "System ready" with the other modules accepted.
10. The Multiboot information block lies in the reserved low 1 MiB.
11. The modules lie above the kernel image and below 4 GiB.

**`scripts/check-multiboot.py`** (Madire's own code) is at least as strict as `grub-file --is-x86-multiboot`: the header within the first 8192 bytes and 4-byte aligned, the magic, the checksum, the flags (refusing unknown required bits), plus the a.out fields (`header_addr`, `load_addr`, `load_end_addr`, `bss_end_addr`, `entry_addr` consistent with each other and with the file).

**Checks that change (33)**, each explained (before, after, why the same fact):
- `kernel has a valid Multiboot header`: `grub-file` → `check-multiboot.py`.
- `[0.10] GRUB default entry is titled 'Madire OS v…'`: read from the first entry of `limine.conf`.
- `[0.7] module (GRUB)` ×2 and `[0.8] module (GRUB): result on the message line`: test ISO built with xorriso and Limine.
- `[0.9.2] keylog test ISO: its grub.cfg differs … only by 'keylog'`: `limine.conf` differs only on the `cmdline:` line.
- `[0.11] ISO: grub.cfg loads the 7 programs …`: from `limine.conf`.
- `[0.10] GRUB Diagnostics …` ×26 (the 16 earlier entries unchanged; 9 user-mode entries with a position check and a boot each; smep and smap with a position check and two boots each; the 27 entries): Limine's `default_entry: Diagnostics/<title>` with `timeout: 0` per test ISO, as GRUB's `set default="1>N"` is today.
- In 3a only the content changes; in 3b the 32 names that contain "GRUB" are renamed (D4).

**Same name, now booted through Limine:** every check on `serial-boot.log` and `serial-boot-keylog.log` in parts 1–3, including the 14 `ISO 128M` memory checks and `[0.11] keylog test ISO: the same 7 program modules accepted`.

## 6. Risks

1. **VirtualBox (medium):** Limine's BIOS boot under VirtualBox on the Windows Hypervisor Platform, and text mode after the hand-off; found early by the stage 1 smoke test.
2. **Memory figures (low):** placement follows GRUB's (information block at `0x10000`, modules after the kernel); the A/B comparison decides.
3. **Fetching at build time (medium):** the build needs GitHub's release download (Actions, Codespace); a wrong hash fails loudly.
4. **`bios-install` modifies files (low):** the pinned-hash check covers only files that stay identical (stage 1 finding).
5. **Diagnostics selection (low):** no title contains `/` or `#`, so `default_entry` paths need no escaping; confirmed on Actions in stage 3a.
6. **Version churn (low):** pinned to v12.9.3; any update is its own deliberate change.
7. **Licence (accepted, D2):** the CC-BY-3.0 origin and the unconfirmed cursor code are recorded as known items.

## 7. Binding rules

- No Actions run while an owner decision is open (P1 before stage 1).
- QEMU timing, stress and kernel-margin evidence from GitHub Actions only; every run used as evidence collected.
- Every stage report: the protected-file diff, "No third-party code added" or the list (Limine is a fetched tool, not code in the repository; its notices are listed when they are added).
- LF, no BOM, no trailing whitespace; commit messages checked for a BOM.
