### B1. Architecture and ABI

**CPU mode: x86-64 long mode, entered by Madire's own stub after a Multiboot 1 hand-off.** Evidence in the code:

| Fact | Where |
|---|---|
| The kernel is an ELF64 x86-64 link (`elf64-x86-64`), flattened to `madire.kernel` for the Multiboot a.out kludge | `linker/linker.ld:22` (`OUTPUT_FORMAT(elf64-x86-64)`), `Makefile:24` (`ld -m elf_x86_64`), `Makefile:30` (`nasm -f elf64`), `Makefile:91` (`objcopy -O binary`) |

| The loader enters `_start` in 32-bit protected mode; the stub checks CPUID, long mode (`0x80000001` EDX bit 29) and PAE | `boot/boot.asm:61-109` |
| Temporary tables (identity 0–4 GiB, physical view, kernel at `0xFFFFFFFF80000000` + 0–1 GiB, 2 MiB pages); CR3, CR4.PAE, EFER.LME (`0xC0000080` bit 8), CR0.PG → long mode | `boot/boot.asm:114-159` |
| Far jump into the 64-bit code segment (L=1), then to the higher half; `kernel_main` called in 64-bit code | `boot/boot.asm:161-162`, `:235-238`, `:242-248` (GDT `0x00AF9A…`), `:258-281` |
| Programs are ELF64 x86-64 only (`ELFCLASS64`, `EM_X86_64`) | `kernel/proc/elf_core.c:65`, `:75` |
| `SYSCALL` set up: STAR (`0xC0000081`, kernel CS 0x08, SYSRET base 0x28\|3), LSTAR = `syscall_entry`, SFMASK, EFER.SCE; read back and logged (`SYSCALL: … read back: OK`) | `kernel/proc/syscall.c:106-120`, `kernel/arch/x86/gdt_desc.h:62-66`, `kernel/proc/syscall.h:25` (SFMASK), called from `kernel/kernel.c:299` |
| Entry: `syscall_entry` switches to the thread's kernel stack (TSS RSP0) | `kernel/proc/syscall_entry.asm:32-35` |
| Today's table: Linux x86-64 numbers 1, 24, 35, 39, 60, 231; every other number `-ENOSYS`; 0x10000000–0x1000FFFF reserved for Madire | `kernel/proc/syscall_core.h:4-45` |

- **System-call table: Linux x86-64** (`syscall_64.tbl`, the "common"/"64" ABI), **not** i386 `int 0x80` (no 32-bit gate exists; the IDT has no vector 0x80 handler for user mode). Number in RAX, arguments RDI, RSI, RDX, R10, R8, R9; result in RAX, errors as `-errno`; RCX and R11 clobbered. Returns stay `IRETQ`.
- Every new call uses the Linux number, argument and structure layouts and errno values (asm-generic numbering). Taken from the documented interface (man pages, the table); no Linux header or code is used. No Madire-range call is added.
- **Structure layouts:** `struct stat` (x86-64, 144 bytes: `st_dev`, `st_ino`, `st_nlink` u64; `st_mode`, `st_uid`, `st_gid` u32; pad; `st_rdev` u64; `st_size`, `st_blksize`, `st_blocks` i64; `st_atim`, `st_mtim`, `st_ctim` as two i64 each; 3 reserved i64); `struct linux_dirent64` (`d_ino` u64, `d_off` i64, `d_reclen` u16, `d_type` u8, `d_name[]`, 8-byte aligned records).
- **Open flags (x86-64):** `O_RDONLY 0`, `O_WRONLY 1`, `O_RDWR 2`, `O_CREAT 0x40`, `O_EXCL 0x80`, `O_TRUNC 0x200`, `O_APPEND 0x400`, `O_DIRECTORY 0x10000`, `O_CLOEXEC 0x80000` (stored; no `exec` yet). Other bits are ignored, as Linux's `open` ignores unknown flags. Access mode 3 → `-EINVAL`.
- **`*at` flags:** `AT_FDCWD` = -100; `AT_SYMLINK_NOFOLLOW 0x100` (accepted, no links exist), `AT_REMOVEDIR 0x200` (`unlinkat`), `AT_NO_AUTOMOUNT 0x800` (accepted, ignored), `AT_EMPTY_PATH 0x1000` (`newfstatat`: stat the dirfd itself). Any other flag bit → `-EINVAL` (Linux's answer).
- **Shared code:** `open`/`openat`, `stat`/`lstat`/`newfstatat`, `mkdir`/`mkdirat`, `unlink`/`rmdir`/`unlinkat` are each one function taking a start folder: the path calls pass the current folder, the `*at` calls pass `AT_FDCWD`'s current folder or the folder of `dirfd`. Supporting a folder `dirfd` costs nothing extra, so it is in from the start (no deviation). If a stage shows otherwise, the approved fallback is `AT_FDCWD` only, with a folder `dirfd` and a relative path answered `-EBADF`, listed as a deviation.

### B2. VFS layer

| Part | Design |
|---|---|
| Layering | `kernel/fs/path_core.{c,h}` (pure: splitting, `.`/`..`, limits), `kernel/fs/vfs_core.{c,h}` (pure: nodes, lookup from a start folder, the operations and their errno decisions, behind an ops table per filesystem), `kernel/fs/ramfs_core.{c,h}` (pure: the RAM filesystem's nodes and page index), `kernel/fs/fspage.c` (kernel side: frames from the PMM through the physical-access window), `kernel/fs/vfs.c` (the kernel glue, the boot self-test), `kernel/proc/klock_core.{c,h}` + `klock.c` (the lock, stage 3). The `_core` files build on the host for unit tests, like `proc_core.c` |
| Nodes | `struct vnode`: type (file / folder), ino, size, times, mode, `nlink`, an open count, the parent, the filesystem's data. Freed when both `nlink` and the open count reach 0 (Linux's unlink-while-open) |
| Mount | One root filesystem (the RAM filesystem), behind the ops table so a disk filesystem can mount later. No `mount` in 1.0 |
| User copies | `read`, `stat`, `getcwd`, `getdents64` need **`copy_to_user`** (new, in `kernel/memory/usercopy*.{c,h}`, not protected) with `user_writable()`, unit-tested like `copy_from_user`. 1.0 adds no unmapping call and no threads inside a process, so the check-then-copy rule (AGENTS.md section 10) is not triggered; stage 4's report says so |

**The VFS lock (D10, stage 3).** One lock, `klock`, for the whole VFS:

| Rule | How |
|---|---|
| Acquire | `klock_try()` under `preempt_disable` (one CPU: a flag and an owner TID). If taken, the waiter calls `thread_yield()` and tries again. **No waiter ever blocks** (no sleep queue in 1.0) |
| **Thread 0 never blocks** | Thread 0 (the console) takes the lock only by the same try-and-yield loop, never a blocking call. This is the rule the scheduler already enforces: for thread 0, `sched_core` answers `SCHED_WOULD_BLOCK` and thread 0 polls (`kernel/proc/thread.c:434`, `:491`; `thread.h:10`). The lock adds no path where thread 0 is taken off the run queue. **New always-on self-check:** `klock` panics if a blocking wait is ever requested by thread 0, and the existing scheduler self-check (no switch to a thread off the run queue while not ready) stays on |
| Holder always makes progress | Holders run with preemption **on** (they may be preempted, never blocked inside the lock). A kill takes effect only at the return to ring 3 or before the first entry (`kernel/proc/process.c:194-199`, `:327-330`), never inside a system call, so a holder always finishes its call and releases the lock. Faults inside the kernel are a panic, not a kill |
| Bounded hold | Each hold covers bounded work: one chunk of at most 4096 bytes of data (two pages at most), one path lookup (PATH_MAX), one folder's entries. File data is copied one page at a time with `preempt_disable` only around each window mapping, so turns stay within the policy (b) bound (no turn over 6 ticks) |
| Large `read`/`write` (F18) | A call on a regular file loops **inside the kernel** in 4096-byte chunks: take the lock, copy one chunk (user buffer ↔ file pages), release the lock, `thread_yield()` if a switch is pending, repeat. It returns the full count (Linux); a short count only at end of file (`read`) or after partial progress followed by an error (`EFBIG`, `ENOSPC`, `EFAULT`) |
| Offsets stay consistent between chunks | The open-file object carries a "busy" mark held for the whole call (Linux's per-file position lock): a second `read`/`write`/`lseek` on the **same** open file (e.g. after `dup`) yields until the first call ends, so its offset never interleaves. A **writer** also marks the node busy for the whole call (Linux's per-inode write lock), so two writes to one file never interleave chunk by chunk; `O_APPEND` claims the end at the start of the call. Readers of the node are not held back (they may see a write in progress, as on Linux). Both marks are waited on by yielding, never blocking |
| Kill or unlink during a loop | A kill takes effect only at the return to ring 3, so the loop ends first (at most 2 MiB / 4096 = 512 chunks per call on a file); an unlinked file stays alive while the call holds its open file |
| Thread 0's wait is bounded | Because each hold is one chunk, thread 0 waits at most one chunk per try (and, for a busy node, one other caller's call); the diagnostic records the longest wait in ticks |
| Not reentrant | Taking it twice from one thread panics (a bug, never a hang) |

### B5. RAM filesystem limits and memory

| Limit | Value | Exact behaviour when hit |
|---|---|---|
| Nodes (files + folders, root included) | **1024** | creating a file or folder → `ENOSPC`; nothing is created |
| File size | **2 MiB** (one 4 KiB index page of 512 frame numbers per file) | `write` crossing it writes up to the limit and returns the short count; at the limit → `EFBIG`; `ftruncate` beyond → `EFBIG`; `lseek` beyond is allowed, the write then fails |
| Data budget | **min(32 MiB, 75 % of the free pages at boot)**, index pages included (a 25 % reserve for programs and the kernel) | a `write` that runs out writes what fits and returns the short count; with 0 written → `ENOSPC`; `ftruncate` growth → `ENOSPC`; the PMM refusing a page under the budget → `ENOSPC` |
| Names and node records | kernel heap, exact size, counted against the 1024 nodes | heap exhaustion → `ENOMEM`, nothing half-created |
| File data | 4 KiB PMM frames through the physical-access window, **not** the heap (at most 16 MiB, never shrinks, `kfree` checks the whole heap) | freed pages go back to the PMM at once |
| Holes | never-written pages read as zeros and cost nothing | — |

**Memory is taken as files grow, never reserved at boot.** At boot the filesystem holds `/`, `/home`, `/tmp` (three node records in the heap, a few hundred bytes) and **0 data pages**; the budget is a ceiling computed once at boot and logged, not an allocation. A file's index page is taken at its first write; data pages as they are written; all are freed when the node is freed.

When quoting arrives, the 9 checks change their input to `prompt "abc>"` with the same expected output.
