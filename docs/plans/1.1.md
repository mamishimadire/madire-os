## F. `scripts/make-wallpaper.py`

- **Usage:** `make-wallpaper.py OUT.png --version X [--layout-json OUT.json] [--print-strokes]`. The Makefile passes `$(MADIRE_VERSION)` (read from `kernel/kernel.h`); S2a passes the harness's `$VERSION`.
- **Standard library only** (`math`, `struct`, `zlib`); no fonts, no images, no randomness, no clock. Output 1024×768 RGB PNG, filter 0, `zlib` level 9, one `tEXt` chunk `Madire-Version`, about 75 KB.
- **Content:** the navy gradient `#0B1220` → `#0F2A4A`, a soft glow behind the logo, the horizon arc in the lower third; the M from `kernel/logo.c`'s four capsule strokes (the same table and the RX/RY aspect correction, drawn smooth with anti-aliasing), `#1E90FF` → `#22D3EE`, the two back strokes darker; `MADIRE` bold and `OS` light with wide spacing, the tagline in `#8B9BB4`, the key hint `↑ ↓ SELECT · ENTER BOOT` 16 px under the panel, `v<version>` bottom-right; original stroke letterforms (capsules on a 14-unit cap height, only the glyphs used).
- **Layout constants** (one place, also written by `--layout-json` for Q2/Q3): header x 308–715, y 36–257; panel 224,276–800,492; hint x 391–632, y 507–519; version x 972–995, y 727–740.
- **Reproducible:** the same Python and zlib give the same bytes (S2a compares within the same job). Across machines the floating-point maths and zlib may differ in the last bit.
- **Existing comparisons of ISO bytes across machines or runs:** `make repro` compares only `madire.elf` and `madire.kernel` (`Makefile:238-253`), so it is unaffected. One existing line compares the ISO across the six jobs of a sharded run: `ISO_IDENTICAL_IN_ALL_JOBS` (`tests/combine-shards.sh:51-53`), **report only, not required** (it is not a check and has no `[tag]`). All six jobs build on the same runner image (the same Python, libm and zlib), so it should keep saying `yes`; if it ever says `no`, nothing fails and the cause is the wallpaper's floating-point maths. `scripts/vbox-acceptance.ps1:139` prints the ISO's SHA-256 (report only). No other check compares ISO bytes.
- **Follow-up (not in 1.1):** integer-only wallpaper maths (as in `kernel/logo.c`), for byte identity across machines.

## K. Risks

1. **The key window under TCG (medium):** Actions' QEMU 8.2.2 reaches Limine later than Kali's; Q1 presses until the menu appears (up to 30 s), so only a menu that never appears fails. Two runs in stage 2.
2. **Text mode at the hand-off on other firmware (medium, untested):** with `quiet`, Limine sets no video mode; SeaBIOS and the VirtualBox BIOS leave 80×25 text (proven). A BIOS that leaves a graphics splash would hide Madire's screen; the fix (the kernel setting mode 3) would change a protected driver and needs its own approval. Real hardware is out of scope (virtual disks only).
3. **Another resolution (low):** if a machine can't give 1024×768, Limine picks another; the wallpaper is centred on `#0B1220`, and the menu window may no longer line up with the panel. Accepted for virtual machines.
4. **Keys during the BIOS on MadireOS-Test (low):** the 0.13 keyboard error didn't reproduce on the scratch VM; the `keywindow` group repeats it on MadireOS-Test.
5. **Floating-point and zlib differences between machines (low):** S2a compares within one job; see F.
6. **The cursor block after Enter (cosmetic):** about 0.1–0.2 s at x 242–250, y 240–255; accepted.
7. **Limine updates (low):** the options and geometry are verified for v12.9.3 only; a Limine update re-runs this plan's probe.
