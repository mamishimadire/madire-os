# Milestone 0.12 Plan: shell improvements, no filesystem

**Base:** `wip/tooling-kali` (`4728a7f`), keeping its script improvements: results in `build\regression\`, the two refusal rules, and the restored Codespace cleanup fix. 0.12 work goes on `wip/0.12`, branched from there; `main` stays at `41f44b8` until the milestone commit.

**Environment:** the Codespace is the only official test environment. Kali stays powered off; its tooling stays in the scripts, documented as optional, and no step needs it.

## 1. Scope

| Item | Design |
|---|---|
| "Did you mean" | When a command isn't found, the existing line `Unknown command: X. Type 'help' for a list of commands.` stays exactly as it is. A second line `Did you mean: help?` is added, naming up to 3 implemented commands within edit distance 2. It's text only, nothing is run, and it fits 79 columns. Pure function in `shell.c`. |
| Help in sections | With a new optional shell-context field, `help` prints section headings between groups (Shell / System / Programs). `help <section>` lists one section. Without the field every output is unchanged, so the protected `test_shell.c` and the existing unit tests stay as they are. |
| `prompt` | `prompt` shows the prompt; `prompt <text>` sets it (see Q3); `prompt default` restores `madire> `. The default never changes, so every `^madire> ` check stays valid. |
| `kill -y <pid>` | Ends the process without asking; the refusals are the same as for `kill`. |
| `sleep <seconds>` | The console waits without blocking thread 0 (a wait state like a foreground program); Ctrl+C cancels it; 1–3600 seconds. |
| `presskey` | Prints `Press any key to continue...` and waits; the key isn't typed. Ctrl+C cancels it. Key logging stays off. |
| `time <command>` | Runs the command and then prints `time: N ticks (X.XX s)`. With `run`, it waits for the program's end line. `time time …` is refused. |
| `alias` / `unalias` | In memory: up to 16 aliases, names `[a-z0-9_]{1,15}`, values up to 63 characters. Only the first word is expanded, once (no recursion), and the result is capped at 71 characters. `alias` and `unalias` can't be aliased. Expansion happens in `shell.c` before parsing, so the protected `parser.c` is unchanged. |
| `set` / `export` / `env` | In memory: up to 32 variables, names `[A-Za-z_][A-Za-z0-9_]{0,15}`, values up to 63 characters. `set NAME=value` sets one, `set` lists them, `export NAME` marks one, `env` lists the exported ones. Passing variables to programs is **deferred**: it needs a process-start ABI for the environment, and with it check-then-copy review. `$NAME` expansion is decision Q5. |
| Bounded diagnostic waits | Every wait for ticks in `schedtest.c` and `usertest.c` (unprotected) gets a limit and a MISMATCH line on timeout. The `test=timer` wait is in the protected `devtest.c` (decision Q8). |
| Per-boot logs | `remote-regress.ps1` also downloads `build/serial-*.log`, the stall captures and the key evidence as one tar. `compare.py` moves into the repository as `scripts/compare-serial.py`, my own code (no external text), so VirtualBox and QEMU logs can be compared. The tool's `[0.11]` summary line takes the tag from `kernel/kernel.h`. |
| Docs | Stage 0 records the NEM/VBS finding: VirtualBox falls back to Windows Hypervisor Platform because VT-x isn't available while VBS runs, for every VM including `MadireOS-Test`. It likely explains the VirtualBox timer bursts seen since 0.9 (unproven). Kali is documented as an optional local target, not used. |

**Out of scope:** pipes, scripts and files (need 1.0); passing the environment to programs; tab completion; anything that changes how programs start.

## 2. Binding rules
- **Check-then-copy:** no new system call, no unmapping, no threads inside a process, so the rule isn't triggered. If environment passing is ever added, the copy into the program's stack must follow the rule.
- **Secret input:** no feature adds a secret prompt. `presskey` reads one key, which is never logged as text, and Ctrl+C stays logged only as its fixed line.
- **Key logging stays off by default.** No new logging path; `presskey` and `sleep` log only fixed lines (for example `console: sleep 5 s`), never typed text.

## 3. Version strings: every check
- `kernel/kernel.h`: `0.11` → `0.12`.
- **QEMU checks built from `VRE`, which change automatically and need no edit:** `qemu-tests.sh` lines 205, 518, 557, 562, 1406, 1958, 2009, 2058, 2110.
- **VirtualBox checks built from `VRe`, also automatic:** `vbox-acceptance.ps1` lines 229 and 362.

## Appendix (PLAN ONLY): GitHub Actions instead of the Codespace
These facts are from memory and need confirming in GitHub's documentation before any decision.
- **Free minutes for private repositories:** GitHub Free includes 2,000 Linux minutes a month (Pro 3,000), counted at 1× for Linux. One run of about 50 minutes uses 50, so about 35–40 runs a month are free. With the default spending limit of $0, usage beyond that is blocked rather than billed.
- **Runner:** `ubuntu-24.04`, the standard runner for private repositories, has about 2 vCPUs, 7 GB of RAM and 14 GB of SSD. It's the same Ubuntu release as the Codespace, so `install-deps.sh` gives the same toolchain (GCC 13.3, QEMU 8.2.2, GRUB 2.12). The kernel hash might even match `0851bd59`, which would have to be verified.
- **KVM:** standard Linux runners now expose `/dev/kvm` (it needs a udev permission step). But the suite is built and timed around software emulation (TCG), and its CPU-feature checks (for example no SMEP/SMAP on `qemu64`) could change under KVM. Recommendation: keep TCG on Actions for parity, and consider KVM only as a separate, approved experiment.
- **Limits:** a job may run up to 6 hours, which is enough. Artifacts (the logs) count against the account's Actions storage (500 MB on Free) and have a retention period, so it should be kept short (for example 7 days).
- **How it would run:** a manually triggered workflow (`workflow_dispatch`), or one triggered by a push to `wip/*`, never by a pull request (AGENTS.md). No secrets are needed. It would check out the exact commit, record the SHA-256 manifest, run `make unit test iso`, and upload the log, the per-boot serial logs and the stall captures.
- **Risks:** shared hosts make timing vary, as in the Codespace; there's no VirtualBox (acceptance stays local); and the workflow file itself is a new tooling file to review.
- **Recommendation:** an optional trial stage, run once side by side with a Codespace run on the same commit. If the results are identical (every check, the unit suites, `make repro`, and ideally the kernel hash), you could decide to make Actions the official environment and keep the Codespace as a fallback. That would make the regression free within the monthly minutes.
